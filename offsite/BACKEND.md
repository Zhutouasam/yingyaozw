# 荧耀站外报价后台

当前前台已按品牌要求暂停“定制推广需求”表单与在线提交入口，首页按钮进入渠道报价；询价单支持本地收藏、复制与导出。后台需求记录与接口保留，前台不展示管理入口。

后台入口：`http://localhost:4173/admin`。首次在本机打开时设置管理员账号与至少 10 位的密码，没有内置默认密码。品牌主页为 `http://localhost:4173/`，报价中心为 `http://localhost:4173/quote`。

## 管理内容

- **报价管理**：搜索、按分类和状态筛选；新增或修改名称、分类、渠道类型、价格、币种、市场 / 平台、发布形式、交付时效、月流量、渠道链接、案例链接、完整服务说明、排序及展示状态。
- **展示状态与删除**：每行提供编辑、上架／下架、删除按钮，操作前显示报价名称并确认。删除后移入回收站，不再出现在默认报价列表和前台；点击工具栏「回收站」可恢复为草稿，核对后再手动上架。没有永久清空操作，备份包含回收站记录。草稿与已下架仍可编辑。报价支持数字、区间、套餐和文本说明；`0` 表示免费，留空表示待确认。
- **分类与业务分组**：新增、改名、调整分组与顺序、隐藏或重新展示。隐藏目录时其所属报价同时从前台隐藏。
- **备份**：下载包含全部报价、草稿、下架记录、分类与分组的 JSON 数据副本。
- **账户设置**：修改管理员密码；修改后其他登录会话失效。会话有效期为 8 小时。
- **客户需求**：查看已接收的产品需求与意向渠道，显示最近 500 份记录，可标记待联系、已联系、已完成。前台提交入口已暂停。仅登录管理员可读取，报价导出不包含客户联系方式。
- **案例图片**：在首页设置下管理，可一次上传多张，最多保存 60 张；填写标题、品类和合作内容后勾选展示，保存后接入首页循环相册。支持上下排序、更换与隐藏；草稿图片仅登录管理员可读取。较大的原图自动压缩，服务器每张最多接收 1 MB 的 PNG、JPG 或 WebP。隐藏图片仍可在后台重新发布。上传前请遮挡客户私人信息。
- **待完善信息**：报价列表可以筛选价格、合作说明或排期尚未填写的记录；请按实际业务补齐或说明不适用，不会自动编造价格。
- **首页设置**：分为首页增长案例和微信合作咨询。156% 作为待核对的初始案例数字保存；补齐实际指标、周期、品类和数据说明，并勾选发布后才显示在首页。微信号与二维码展示在首页“如何合作”；二维码支持上传、预览、更换与移除，点击“保存首页设置”后生效。图片支持 PNG、JPG、WebP，最大 512 KB，请保留完整二维码及四周白边。未上传时显示待更新占位；邮箱仅保留在后台设置中。

保存后，已经打开的前台通过同浏览器标签页通知更新；切回页面时也会更新，其他浏览器最多 30 秒后自动刷新数据。刷新数据不会重置现有搜索和筛选，失效分类或筛选会自动调整。

首页与案例设置显示未保存提示，切换后台菜单、退出或重新读取时会确认；刷新或关闭页面使用浏览器的离开提醒。报价、分类及分组编辑也提供刷新前的未保存保护。报价目录更新时间与首页内容分开记录，修改二维码或案例图片不会刷新报价日期；渠道详情显示该条报价的最后修改日期，该日期不等同于业务价格核实日期。

## 开发与生产运行

需要 **Node.js 24+**，使用其内置 SQLite；无需额外安装数据库服务。

```sh
npm install
npm run dev -- --port 4173 --strictPort
```

开发模式由 Vite 在同一端口挂载真实 API。生产模式：

```sh
npm run build
npm start
```

`npm start` 读取可选的 `.env`。可将 `.env.example` 复制为 `.env`，设置端口和数据库路径。生产模式同时提供静态前台、后台和 API，不能只把 `dist` 上传到纯静态托管服务。

上线时用进程管理器运行 Node 服务，以 Nginx 或托管平台提供 HTTPS；设置 `PUBLIC_ORIGIN` 为真实域名，如 `https://your-domain.example`，确保反向代理保留正确的 Host。需要允许外部直接连接时设置 `HOST=0.0.0.0`。数据库目录必须使用可持久化且允许写入的磁盘；单机 SQLite 不适合多个实例各自使用独立磁盘的部署方式。

首次账号初始化默认只允许服务器本机访问。远程首次初始化需要先在环境中设置随机 `BOOTSTRAP_TOKEN`，再在初始化页面展开「远程部署的初始化密钥」并填写同一值。账号创建后初始化接口关闭，可以从环境中移除该密钥。

## 数据与保存

默认数据库位置：`server/data/pricing.sqlite`，使用 WAL 和数据库事务。数据库、会话及 `.env` 均已加入 Git 忽略列表。

第一次启动自动导入原有 612 项报价和完整 17 条分类元数据（其中 15 类显示中），保留 4 个业务分组；重启不会重新导入，更不会覆盖后台修改。`public/data/snow123-pricing.js` 是初始化种子，旧 `/data/` 路径已停止公开提供；前台唯一报价来源为 `/api/catalog`。`npm run sync:pricing` 只更新种子文件，不会更新已初始化的数据库。

数据库备份应使用 SQLite 的在线备份机制，或先停止服务再备份整个 `server/data` 目录，避免只复制仍在运行中的主数据库文件而遗漏 WAL。后台 JSON 下载是可读的数据导出；当前未提供在线 JSON 导入或自动定时备份。已保存的历史修改版本不支持回滚，但下架记录仍可再次编辑。

询价单支持本地保存、复制与导出，目前没有在线提交入口。保留的需求接口最多接受 50 项意向渠道，后端根据当前可见报价生成参考明细，不接受客户端自报价格；该接口不会自动发送邮件或外部消息通知。

首页构建时生成 `dist/home.html`，生产 Node 服务和 Vite 预览均直接返回品牌正文，浏览器再接管导航和交互。首页只读取轻量 `/api/home` 摘要，报价中心继续使用完整 `/api/catalog`。Node 生产服务对 HTML、JS、CSS 与 JSON 提供 gzip，对带哈希的构建资源启用长期缓存。正式上线前在 `.env` 中设置真实 `PUBLIC_ORIGIN`，重新运行 `npm run build`，即可生成首页 canonical 和完整分享 URL；未设置域名时不会杜撰 canonical。

## 接口

| 路径 | 用途 |
| --- | --- |
| `GET /api/catalog` | 前台已发布且目录可见的报价 |
| `GET /api/home` | 首页统计、可见分类、公开顾问联系方式与已发布案例 |
| `GET /api/wechat-qr` | 已配置的微信二维码图片，未设置时返回 404；首页摘要只返回图片地址 |
| `GET /api/case-images/:id` | 公开已发布案例图片；登录管理员可读取草稿图片 |
| `GET /api/admin/cases`、`POST /api/admin/cases`、`PATCH /api/admin/cases/:id` | 读取、新增和更新案例截图，写入需登录、CSRF 和最新版本 |
| `POST /api/inquiries` | 提交产品需求，需同源、同意合作沟通及唯一提交凭证 |
| `GET /api/admin/inquiries` | 私密需求列表，需要登录 |
| `PATCH /api/admin/inquiries/:id` | 更新需求处理状态，需 CSRF 和最新版本 |
| `GET /api/admin/site`、`PATCH /api/admin/site` | 获取或维护首页设置，需要登录，写入需 CSRF 和最新版本 |
| `GET /api/auth/session` | 登录与首次初始化状态 |
| `POST /api/auth/setup` | 首次创建管理员 |
| `POST /api/auth/login`、`logout`、`password` | 登录、退出、修改密码 |
| `GET /api/admin/catalog` | 全部后台数据，需要登录 |
| `GET /api/admin/export` | 完整 JSON 导出，需要登录 |
| `POST /api/admin/records`、`categories`、`groups` | 创建记录、分类、分组 |
| `PATCH /api/admin/records/:id`、`categories/:id`、`groups/:id` | 修改对应信息，携带最新 `version` |
| `PATCH /api/admin/records/:id/status` | 快捷上架、下架、移入回收站或恢复草稿；需登录、CSRF 与最新 `version`，仅修改状态 |

会话使用 HttpOnly、SameSite=Strict Cookie，HTTPS 配置下附带 Secure；密码使用随机盐与 scrypt 哈希。后台写入要求会话中的 `X-CSRF-Token` 并校验同源；SQL 使用参数化查询，链接限制为 HTTP / HTTPS。修改使用版本校验，旧版本提交返回 409，避免覆盖其他窗口已经保存的修改。登录连续失败 10 次后同一来源暂停 15 分钟。

## 验证

```sh
npm run test:backend
npm run build
```

自动测试使用独立的临时数据库，验证完整初始化、认证与 CSRF、全部字段保存、文本和小数报价、草稿及下架、目录隐藏、版本冲突、重启持久化、备份、密码更新、退出和登录限流。浏览器验证也使用独立数据库，不会向你的正式报价写入测试内容或预设管理员密码。

需求接口同一连接来源每 15 分钟最多 5 份新需求；相同凭证、相同内容的重试返回原需求编号。本机 Nginx 等可信反向代理部署可设置 `TRUST_LOCAL_PROXY=1`，后端只在连接来源为 loopback 时使用 `X-Forwarded-For` 最后一个有效 IP；代理须正确追加真实连接来源，Node 不应对公网暴露此信任配置。默认忽略客户端转发头。这样不会让多个访客共用本机代理的 5 份额度。其他代理拓扑应在代理层设置客户端限流。需求与首页设置均随 SQLite 持久保存，完整数据库备份包含这些新增内容。
